HTML Structure & Document Anatomy

Every webpage is a structured document. Understanding what goes where — and why — is the foundation of everything else.

📄 The Complete HTML5 Document

Every valid HTML page starts with this exact skeleton. Open your browser's DevTools on any major website — you'll see this same structure.

<!-- Line 1: MUST be first. Tells browser to use HTML5 standards mode --> <!DOCTYPE html> <!-- Root element. lang= helps screen readers and SEO --> <html lang="en"> <head> <!-- CHARACTER SET — always first inside head --> <meta charset="UTF-8"> <!-- VIEWPORT — makes site responsive on mobile --> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <!-- SEO meta tags --> <meta name="description" content="Page description for Google (150-160 chars)"> <meta name="keywords" content="html, web, tutorial"> <!-- Shows in browser tab + Google search result title --> <title>My Awesome Website</title> <!-- Favicon (icon in browser tab) --> <link rel="icon" href="favicon.ico"> <!-- External CSS --> <link rel="stylesheet" href="styles.css"> </head> <body> <!-- All VISIBLE content lives here --> <h1>Hello World</h1> <p>My first paragraph.</p> <!-- JS at bottom of body = page renders before scripts run --> <script src="app.js"></script> </body> </html>

Element Nodes

Every HTML tag becomes an element node. Can have children, attributes, and event listeners attached via JS.

Text Nodes

The actual text content between tags. Even whitespace is a text node! Often forgotten by beginners.

Attribute Nodes

id, class, href, src etc. Accessible via JS: element.getAttribute('href') or element.id

JS Can Change Everything

document.getElementById(), querySelector(), innerHTML — all navigate this tree to read/update the page live.

🌟 Real-World: Google Crawls Your <head>

When Googlebot visits your site it reads the <head> to decide how to rank and display you in search results. The <title> tag becomes your blue clickable link. The <meta description> becomes the grey snippet below it. A missing or poorly written description costs you click-through rate even when you rank #1. Companies like Shopify, HubSpot, and WordPress auto-generate these from page content for exactly this reason.

💼 Interview Questions
  • Q: What does <!DOCTYPE html> do?
    Switches browser into standards mode (vs quirks mode which mimics old IE bugs). Without it you get inconsistent rendering across browsers. Always first line.
  • Q: Difference between <head> and <body>?
    <head> = metadata (title, CSS links, meta tags, scripts) — not visible. <body> = all visible content. Browser parses head first to know what resources to download before rendering.
  • Q: What is the DOM and why does it matter for JavaScript?
    DOM is the browser's tree-structured representation of HTML. JS interacts with the DOM to dynamically change content, style, and structure without reloading the page. React/Vue/Angular are all just fancy ways to manipulate the DOM efficiently.
  • Q: Why put <script> at the bottom of <body>?
    HTML renders top to bottom. Script in <head> blocks rendering until JS downloads and executes. Bottom placement means users see content faster. Alternatively use defer or async attributes on the script tag.

Text Formatting Tags

HTML gives you tags that carry meaning, not just appearance. The difference matters for accessibility, SEO, and screen readers.

📐 Headings — h1 through h6

Headings define page hierarchy. Google uses them to understand your content. Screen readers use them to navigate. Think of them as your document's outline.

h1 — Main Page Title (ONE per page!)

h2 — Major Section (About, Services, Contact)

h3 — Sub-section (What We Do, Our Team)

h4 — Minor heading

h5 — Rarely needed
h6 — Smallest, use sparingly
⚠️ Common Mistake: Don't use headings just to make text big. Use them for hierarchy. Use CSS for size. One <h1> per page — it tells Google what the page is about. Multiple h1s confuse crawlers.

🌟 Real-World: Stack Overflow's Answer Formatting

Stack Overflow uses almost every text tag in answers. Code snippets use <code> and <pre>. Keyboard shortcuts use <kbd>. Important warnings use <strong>. Deprecated solutions get <del>. When you write a Stack Overflow answer in Markdown, the engine converts it to semantic HTML — meaning every piece of formatting maps to a tag with actual meaning, not just visual style.

💼 Interview Questions
  • Q: Difference between <strong> and <b>?
    <strong> has semantic importance — screen readers stress the word when reading aloud, and search engines give it weight. <b> is purely visual bolding. Always prefer <strong> for meaningful emphasis.
  • Q: When would you use <em> vs <i>?
    <em> for real spoken emphasis: "I did <em>not</em> say that". <i> for alternate voice — ship names, technical terms, foreign phrases: "the <i>Lorem Ipsum</i> text".
  • Q: How many <h1> tags per page?
    One. It represents the main topic of the page. Multiple h1s dilute your SEO signal. Use h2–h6 for hierarchy. Exception: inside <article> or <section> elements you may have sub-h1s, but the convention is still one per page.
  • Q: When to use <br> vs margin in CSS?
    Use <br> only when the line break is part of the content (poem, address, song lyrics). For spacing between elements — always use CSS margin/padding. <br> inside a paragraph just for visual spacing is bad practice.

HTML Forms

Forms are how users send data to servers — every login, signup, search, checkout and feedback you've ever seen is an HTML form.

🧬 Form Anatomy

<!-- action: WHERE data goes | method: HOW it's sent --> <form action="/api/register" method="POST" novalidate> <!-- label's for= must match input's id= — links them for click + accessibility --> <label for="email">Email Address</label> <input type="email" id="email" name="email" placeholder="you@example.com" autocomplete="email" required> <!-- name= is the KEY sent to server. Without it, value won't be submitted! --> <input type="password" id="pwd" name="password" minlength="8" required> <!-- fieldset groups related inputs; legend = group title --> <fieldset> <legend>Account Type</legend> <input type="radio" id="r1" name="type" value="personal" checked> <label for="r1">Personal</label> <input type="radio" id="r2" name="type" value="business"> <label for="r2">Business</label> </fieldset> <!-- type="submit" submits the form; type="reset" clears all fields --> <button type="submit">Create Account</button> <button type="reset">Clear</button> </form>

💼 Interview Questions
  • Q: Difference between GET and POST form methods?
    GET appends data to URL (?name=value) — visible, bookmarkable, limited size (~2000 chars), cached. POST sends in body — invisible, no size limit, not cached. Use GET for search (shareable URL), POST for login/signup/payment (sensitive data).
  • Q: What does the name attribute do? What if it's missing?
    name is the key in the key=value pair sent to server. Without name, the input value is silently ignored and never submitted. id is for CSS/JS. name is for the server. They can be the same but serve different purposes.
  • Q: What is enctype="multipart/form-data"?
    Needed when uploading files. Default enctype (application/x-www-form-urlencoded) can't handle binary data. multipart splits the request into multiple parts — one per field. Without it, file uploads arrive as empty on the server.
  • Q: Difference between disabled and readonly?
    disabled: greyed out, not sent to server, not focusable. readonly: can be focused and copied, value is sent to server, can't be edited. Use readonly for things like auto-filled order IDs. Use disabled for truly inactive fields.
  • Q: How to prevent form submission with JavaScript?
    event.preventDefault() in the submit listener. Lets you validate first, show custom errors, or send via fetch/AJAX instead of full page reload. Pattern: form.addEventListener('submit', e => { e.preventDefault(); /* validate then fetch */ })

HTML Tables

Tables are for tabular data — rows and columns of related information. Never use them for page layout. That's what CSS Grid and Flexbox are for.

🧩 Complete Table Anatomy

<table> <!-- caption: table title for accessibility (like h1 for the table) --> <caption>Top 3 Crypto Prices — 9 May 2025</caption> <!-- thead: header row(s) — repeats when printing long tables --> <thead> <tr> <th scope="col">Coin</th> <th scope="col">Price (USD)</th> <th scope="col">24h Change</th> <th scope="col">Market Cap</th> </tr> </thead> <!-- tbody: actual data rows --> <tbody> <tr> <th scope="row">Bitcoin (BTC)</th> <td>$62,450</td> <td style="color:green">+2.4%</td> <td>$1.22T</td> </tr> <tr> <th scope="row">Ethereum (ETH)</th> <td>$3,120</td> <td style="color:red">-0.8%</td> <td>$374B</td> </tr> </tbody> <!-- tfoot: summary/total row(s) --> <tfoot> <tr> <td colspan="4">Data source: CoinGecko API</td> </tr> </tfoot> </table>

↔️ colspan & rowspan — Merging Cells

colspan merges horizontally across columns. rowspan merges vertically across rows. These are how spreadsheet-style merged cells work.

<!-- colspan="2" = this cell takes up 2 columns --> <tr> <th colspan="2">Full Name</th> <!-- covers "First" and "Last" columns --> <th>Score</th> </tr> <tr> <td>John</td> <td>Doe</td> <!-- rowspan="2" = this cell takes up 2 rows --> <td rowspan="2">95</td> </tr> <tr> <td>Jane</td> <td>Smith</td> <!-- no 3rd td here — rowspan above covers it --> </tr>

🌟 Real-World: GitHub Repository Table

GitHub's repository list, Binance order book, Google Analytics reports — all HTML tables. GitHub uses scope="col" on <th> elements for accessibility so screen readers announce column context. The sortable columns use JavaScript to re-order <tr> elements inside <tbody> without reloading. The "sticky header" effect (column names stay visible while scrolling a long table) is done with CSS position: sticky; top: 0 on <thead>. The alternating row colours (zebra striping) come from CSS tr:nth-child(even).

💼 Interview Questions
  • Q: Should tables be used for page layout?
    Absolutely not. Tables for layout was 1990s practice. Problems: inaccessible (screen readers read cell by cell), terrible on mobile (no responsiveness), poor SEO, impossible to maintain. Use CSS Grid for 2D layout, Flexbox for 1D. Tables = data only.
  • Q: Difference between <th> and <td>?
    <th> is a table header cell — bold and centred by default, but more importantly it's announced as a header by screen readers. <td> is a data cell. Use scope="col" or scope="row" on <th> to tell screen readers the header's direction.
  • Q: Purpose of <thead>, <tbody>, <tfoot>?
    Semantic grouping. <thead> and <tfoot> repeat when printing long tables across pages. Browser can scroll <tbody> independently (overflow: scroll on tbody) while keeping headers/footers fixed. Also helps assistive tech and CSS targeting (tbody tr:hover).
  • Q: What is the scope attribute on <th>?
    Tells assistive tech whether the header applies to a column (scope="col") or a row (scope="row"). Critical for complex tables with both row and column headers. Without scope, screen reader users can't tell which header applies to which data.
