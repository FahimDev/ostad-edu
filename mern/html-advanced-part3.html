Multimedia — Images, Audio & Video

Media elements are everywhere on the web. Knowing the right attributes and formats is what separates fast, accessible sites from slow broken ones.

🖼️ The <img> Element — Every Attribute Matters

<!-- ── BASIC IMAGE ── --> <img src="photo.jpg" alt="A developer typing code on a laptop" width="800" height="450"> <!-- ── RESPONSIVE IMAGE — different sizes for different screens ── --> <img src="photo-800.jpg" srcset="photo-400.jpg 400w, photo-800.jpg 800w, photo-1600.jpg 1600w" sizes="(max-width: 600px) 400px, (max-width: 1200px) 800px, 1600px" alt="Responsive photo" loading="lazy"> <!-- ── PICTURE — art direction + format fallback ── --> <picture> <!-- AVIF: smallest file, newest browsers --> <source srcset="photo.avif" type="image/avif"> <!-- WebP: ~30% smaller than JPEG, wide support --> <source srcset="photo.webp" type="image/webp"> <!-- JPEG fallback for old browsers --> <img src="photo.jpg" alt="My photo" loading="lazy"> </picture> <!-- ── FIGURE + FIGCAPTION — semantically connected image+caption ── --> <figure> <img src="chart.png" alt="Q4 2024 revenue growth chart"> <figcaption>Figure 1: Revenue grew 40% in Q4 2024</figcaption> </figure>

alt attribute

Screen readers read it aloud. Shows if image fails. Helps SEO. Empty alt="" for purely decorative images (icons used as bullets etc).

width + height

Always set both! Browser reserves space before image loads. Without them you get Cumulative Layout Shift (CLS) — content jumping around = bad UX + bad Core Web Vitals score.

loading="lazy"

Native browser lazy loading. Images below the fold load only when they're about to scroll into view. Zero JS required. Use on all images except above-the-fold hero images.

srcset + sizes

Browser downloads the most appropriate image for screen size and DPI. Mobile gets 400px file, desktop gets 1600px. Massive bandwidth savings on mobile.

🗂️ Image Formats — Choosing the Right One

.avif
Best for: Photos, illustrations

Newest format. 50% smaller than JPEG. Chrome, Firefox support. Use with <picture> fallback.

.webp
Best for: Photos + transparency

Google's format. ~30% smaller than JPEG. Supports transparency unlike JPEG. 95%+ browser support. Use today.

.jpg / .jpeg
Best for: Photos

Universal support. No transparency. Lossy compression. Still useful as <picture> fallback for old browsers.

.png
Best for: Transparency needed

Lossless compression. Supports transparency (alpha channel). Good for logos with transparent bg. Larger than WebP.

.svg
Best for: Icons, logos, charts

Vector — infinitely scalable, no blur at any size. Code-based (XML). Can be styled with CSS. Inline <svg> lets JS animate it.

.gif
Best for: Simple animations

Only 256 colours, huge file size. Use CSS animations or <video autoplay loop muted> instead for better performance.

🌟 Real-World: How Netflix Serves Video

Netflix doesn't use a plain <video> tag. They use Adaptive Bitrate Streaming (ABR) via MPEG-DASH or HLS protocols. The video file is split into small 2–10 second chunks at multiple quality levels (480p, 720p, 1080p, 4K). The player constantly monitors your connection speed and switches quality mid-stream — that's why your video doesn't stop when your WiFi slows down. The <video> element's src points to a manifest file (.mpd or .m3u8), not a single video file. DRM (Widevine, FairPlay) encrypts each chunk. The custom controls (skip intro, next episode, quality selector) are built with JavaScript over a basic <video> element with no controls attribute.

💼 Interview Questions
  • Q: Why is alt text important on images?
    Three reasons: (1) Accessibility — screen readers read it aloud to blind users. (2) SEO — Google indexes alt text to understand image content. (3) Fallback — displayed when image fails to load. Alt="" (empty) for decorative images tells screen readers to skip them.
  • Q: What is loading="lazy" and why use it?
    Native browser lazy loading — images off-screen aren't downloaded until the user scrolls near them. Zero JavaScript needed. Reduces initial page load size dramatically. Don't use on above-the-fold images (hero images, logo) — use loading="eager" or omit the attribute.
  • Q: Difference between SVG and Canvas?
    SVG: vector-based, DOM nodes (CSS-styleable, clickable, accessible), infinite scalability, re-draws on state change. Canvas: pixel/raster, JavaScript API only, better for 1000s of elements (games), no accessibility. Use SVG for charts/icons/UI elements, Canvas for games/photo editing/complex visualizations.
  • Q: What does muted do on a video tag?
    Silences audio. Critical because browsers block autoplay video with sound (to prevent annoying ads). Autoplay + muted = works everywhere. Used for hero background videos (Apple.com, Airbnb landing pages) and animated product demos.

Semantic HTML

Semantic elements describe their meaning. <article> means "this is self-contained content". <nav> means "these are navigation links". Without semantics, search engines guess — and often guess wrong.

🌟 Real-World: How Google Reads Semantic HTML

When Googlebot crawls a page, semantic HTML gives it strong signals: <article> tells it this is a distinct piece of content. <time datetime="..."> tells it exactly when the content was published (crucial for "fresh" ranking). <nav> helps it understand your site's link structure. <main> tells it to focus there and ignore boilerplate headers/footers. Medium, BBC, and The Guardian all use precise semantic HTML — that's partly why their articles rank so well. A page full of <div>s forces Google to guess at structure. A semantically marked-up page hands it a map.

💼 Interview Questions
  • Q: What is semantic HTML and why does it matter?
    HTML where the tag communicates meaning, not just visual style. Matters for: (1) SEO — search engines understand content structure. (2) Accessibility — screen readers navigate by landmarks. (3) Maintainability — code self-documents. (4) CSS/JS targeting — easier to write selectors like article > header vs div.container > div.top.
  • Q: Difference between <article> and <section>?
    <article> is independently redistributable — would still make sense as a standalone RSS feed item, tweet, or blog post. <section> is just thematic grouping within a page — it needs surrounding context. A page can have one <article> with multiple <section>s, or multiple <article>s (like a news feed).
  • Q: Can <header> and <footer> appear multiple times?
    Yes. They can be used for page-level header/footer AND as headers/footers inside <article> or <section> elements. Only <main> is restricted to one per page.
  • Q: When should you use <div> instead of semantic elements?
    When no semantic element accurately describes the content. <div> is for layout and styling hooks when there's no semantic meaning to convey. Rule of thumb: always ask "is there a more meaningful element?" first. If yes, use it. If no, use <div>.

What happens when you type a URL and press Enter?

DNS lookup → TCP handshake → HTTP/HTTPS request → Server processes → Response received → Browser parses HTML → DOM built → CSS applied → JS executed → Page rendered. Each step can be optimised with caching, CDNs, and compression.

Difference between localStorage and sessionStorage?

Both store key-value pairs in the browser. localStorage persists until explicitly cleared (survives tab close, browser restart). sessionStorage is cleared when the tab closes. Both are synchronous and limited to ~5MB. Neither is secure for sensitive data — servers can't set them.

What is the Critical Rendering Path? (starts open)

The sequence: Parse HTML → Build DOM → Parse CSS → Build CSSOM → Combine into Render Tree → Layout (positions/sizes) → Paint (pixels) → Composite (layers/GPU). Optimising it (minimize render-blocking resources, inline critical CSS) is key to fast First Contentful Paint.

When should you NOT use semantic HTML?

When you only need a generic container for styling/JS purposes and no semantic element fits. Also inside highly dynamic React/Vue components where the structure changes constantly — though even then, keeping semantic roots (main, header) at the app level is good practice.

✅ Why this beats custom JS accordions: Works without JavaScript (resilient). Keyboard accessible (Enter/Space to toggle). Screen readers announce "expanded" / "collapsed" states automatically. Browser remembers open state on back navigation. Only add JavaScript if you need group behaviour (one open at a time).

💬 <dialog> — Native Modal

The native dialog element is the correct way to build modals in 2024+. It handles focus trapping, Escape key, backdrop, and accessibility out of the box.

🔗 Links, Buttons & Accessibility Rules

<!-- ── LINKS: for navigation ── --> <a href="/dashboard">Go to Dashboard</a> <!-- External link: rel="noopener noreferrer" REQUIRED for security --> <a href="https://github.com" target="_blank" rel="noopener noreferrer"> GitHub (opens in new tab) </a> <!-- Download link --> <a href="/resume.pdf" download="JohnDoe_Resume.pdf">Download Resume</a> <!-- Tel / mailto --> <a href="tel:+8801XXXXXXXXX">Call Us</a> <a href="mailto:hello@example.com">Email Us</a> <!-- ── BUTTONS: for actions ── --> <button type="button" onclick="handleClick()">Perform Action</button> <button type="submit">Submit Form</button> <button type="button" disabled aria-disabled="true">Unavailable</button> <!-- ⛔ WRONG — never use div as button --> <div onclick="doSomething()" class="btn">Click</div> <!-- ❌ Not keyboard accessible. No Enter/Space. No focus. No role. -->

Use <a> when…

…navigating to a URL, downloading a file, triggering tel:/mailto:. Has an href. Right-click menu, open-in-new-tab all work correctly.

Use <button> when…

…performing an action with no URL: submit form, open modal, toggle dark mode, add to cart. Keyboard accessible by default.

Never use <div onclick>

Not focusable by keyboard. No Enter/Space trigger. Screen readers won't announce it. If you must, add tabindex="0", role="button", and keyboard handlers. Just use <button>.

rel="noopener noreferrer"

Security: without it, the new page's window.opener references your page and could redirect it. Always add when using target="_blank". Modern browsers partially fix this but always include it.

🌟 Real-World: Twitter/X's Accessibility Implementation

The like button on Twitter/X looks like a simple ❤️, but inspect it and you'll find: role="button", aria-label="Like this tweet", aria-pressed="false" (becomes "true" after click). The notification counter has aria-live="polite" so screen readers announce new numbers without interrupting. The tweet composer has aria-multiline="true" and aria-label="Tweet text". All modals use <dialog> with focus trapping. This isn't charity — Twitter has paid settlements for accessibility lawsuits. Proper ARIA is legal protection as much as UX.

💼 Interview Questions
  • Q: What is ARIA and when should you use it?
    Accessible Rich Internet Applications — attributes that add semantic meaning when HTML alone can't express it. Rule: "No ARIA is better than bad ARIA." First try native semantic HTML. Use ARIA only when: building custom widgets (tabs, sliders, tree views), icon-only buttons need labels, or dynamic content needs live announcements (aria-live).
  • Q: What is rel="noopener noreferrer" and why is it important?
    Security pair for target="_blank". noopener: new page can't access window.opener (prevents redirect attacks — malicious page redirects your page to phishing site). noreferrer: also hides the referring URL from the destination (privacy). Always use both together on external links.
  • Q: Difference between <progress> and <meter>?
    <progress> = temporal completion (file upload, loading steps — moving toward a goal). <meter> = static measurement within a range (disk usage, score, temperature). The semantic difference matters: progress implies change over time, meter implies a current reading.
  • Q: Why should you never use <div onclick> as a button?
    Keyboard inaccessible (no Tab focus, no Enter/Space trigger). No semantics (screen reader announces it as generic element). No built-in states (no :focus, :active, disabled). Costs you nothing to use <button>, which has all of this built in.
  • Q: What does tabindex do?
    Controls keyboard focus order. tabindex="0": added to natural tab order. tabindex="-1": focusable via JS (.focus()) but not Tab key — used for modal dialogs to manage focus. tabindex="1+" : avoid! Creates custom focus order that's confusing and hard to maintain.
